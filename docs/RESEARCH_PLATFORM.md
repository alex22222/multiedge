# 服务器研究与 Paper 平台

## 目标与验收

把已验收的 Multi-Edge 核心放入可持续使用的研究闭环：任务来源 → 候选池 → 单股三层证据 → Paper 验证 → 独立指标实验。持续进度记录在 `LOOP_STATE.md`。

验收要求为页面可访问、原始 Google 基准不漂移、真实任务产物可追溯、缺失数据如实展示、Paper 可对账且不倒填交易、指标配置可版本化。一次扫描不是策略收益验证，测试通过也不等于实盘有效。

## 原始规则与个人实验

`edges.py`、`engine.py`、`Config` 的原始判定规则保持冻结。新增 `experiments.py` 提供两种独立模式：

- `baseline_filter`：原始 BUY 同时满足启用的 RSI/MACD 条件后保留；过滤失败显示 WATCH，不把原始 WATCH/NO 升级。
- `custom`：只按明确启用的个人指标输出实验 BUY/NO，至少启用一个指标；原始判定并列显示。

配置按内容哈希产生不可变版本，名称、模式、周期和阈值均保留。修改配置会产生新版本与独立 Paper 账户，不重写旧结果。

RSI 使用 Wilder 算术均值种子和平滑；全平价格为50，只有上涨为100，只有下跌为0，缺失行情重新暖机。MACD 使用 `adjust=False` 的 EMA，首个价格为种子，快/慢/信号线分别暖机；过滤条件是 `MACD > signal` 的状态，不是当日金叉。

## 三层认识

对应 `VIEWPOINTS.md` C1/C2/C6：

| 层 | 呈现 | 来源边界 |
|---|---|---|
| 认知 | 真实催化剂、基本面驱动、事件日期和原始来源 | 引擎跳空仅为价格代理；没有公告来源时标待核验 |
| 直觉 | 主题、行业领涨、群体联动与资金流证据 | 没有来源时留待研究，不生成假评分 |
| 技术 | 七项边缘、MEA、冻结趋势线、验证清单与退出参考 | 来自保存的引擎输出，不由网页重算 |

页面允许补充认知/直觉证据，记录来源链接、事件日期和实际登记时间。用户记录不自动变成独立核验结论。

## 任务产物与数据源

`jobs import-multica` 只导入真实单股附件和冻结名单。完整名单中的缺失明细显示 MISSING；任务声明的汇总 `claimed_counts` 与已取得明细的 `counts` 分别保存。任务 `in_review` 不能显示成已完成。原始报告缺少图表行情时，只渲染原始 JSON 数字并明确图表缺失。

SATU-107 首次导入时：名单101只，真实单股附件5份，任务记录汇总 BUY2/WATCH44/NO55。该状态会随补充产物形成新的不可变快照；首次导入不代表已独立复跑全部101只。

原始验收缓存仍为 MarketWatch。目标服务器访问该站被要求执行浏览器脚本；新增服务器扫描明确使用 Yahoo Finance chart，并保存到独立 `data/yahoo`。没有默默替换原始缓存，也不把新源结果称为 SATU-107 原始交付。

Yahoo 扫描使用接口 OHLC 的 `Close`，不使用 `Adj Close`。后者会包含分红/拆股调整，见 [Yahoo 官方说明](https://help.yahoo.com/kb/SLN28256.html)。每次请求保存原始 JSON、CSV、哈希、真实区间、纽约交易日期、企业行动和取得时间；命中缓存时验证内容。企业行动总回报不在首版会计范围。

## Paper 规则

历史发布 `5751f20` 的195项测试和旧固定示例回执保留于 `2026-11-18-DEPLOYMENT.md`。该版本曾把3%／5%止损、25%目标的举例设为默认，现按用户更正改为以下结构方案。修正版 `9950072` 已部署，本地与服务器216项测试、独立复核、旧账本完整性和生产浏览器核验通过；新账户真实登记后开始处理。

旧版本持仓移动止损 `structure_ma20_hl_v1` 的262项测试及真实登记/出场回执保留为历史。AMGN/MMM复盘发现初始远端E1保护与后来纯均线上调不一致；新默认采用以下独立v2，不改旧两笔成交。

### 独立结构回踩版本 v2

版本`structural_retest_v2`只用于前向5分钟结构Paper，原选股引擎与Google参考值冻结。日线扫描将原始BUY登记为候选，不直接买入；RSI/MACD可附加过滤，但自定义配置不将原始WATCH/NO升级为本版成交。3R、1/2ATR容差、0.1ATR缓冲和确认方式均是本项目研究假设，不是视频给出的完整算法，可能显著减少交易。

1. **来源一致。** 入场计划日线必须与原报告的`source_hash`/价格哈希一致，并在实际观察时间前取得；保留原始/CSV哈希、取得时间和计划指纹。不把后来修订的行情与旧报告结构拼接。失败候选显示`invalid_daily_plan`和具体原因。
2. **初始近端结构。** 用原报告`pullback_age`标明的动能峰之后完整日线最低点作为本次回调锚。必须有成熟均线区和至少另一条成熟水平/趋势线结构，聚类跨度不超过2ATR；回调低点距共振带不超过1ATR。初始止损取`min(本次低点, 共振带下沿)−0.1ATR`，向下取整到美分。远离本次共振带的旧E1不再自动拉低止损。
3. **可评估的收益空间。** 无有效前高目标、目标低于入场或成本后参考RR不足3时拒绝。参考RR采用信号收盘估算，仅为登记检查；实际模拟买入价仍要重验。止损与目标卖出均扣滑点和费用，买入也含滑点和费用，`净RR=净目标收益/净止损风险`。
4. **真实回踩确认。** 仅在下一实际交易日，检查真实登记之后完整5分钟K线。从登记/观察与交易时段起点的较晚者向上取5分钟边界，直到确认必须逐根连续；缺行情拒绝本次计划，不跨缺口推测结构仍有效。任何已登记后K线跌破原结构止损先取消计划。确认要求最新完整K线低点触及共振带上沿加缓冲、未破止损，收盘收复带上沿且收盘高于开盘。
5. **确认后才允许未来成交。** 保存确认K线与实际观察时间。开盘早于该观察时间的K线不能成交；例如13:35–13:40确认、13:40:10收到，13:40开盘已发生，应等待13:45或更晚的合格开盘。确认之后仍须同一会话且行情连续。实际开盘需高于止损、不低于支撑下沿，含滑点价不超过带上沿+1ATR，扣双边成本后仍至少3R；否则拒绝并保留实价核验。超过下一交易日的信号作废。
6. **统一后续结构。** 移动止损不再单凭均线上行触发。只有入场日之后形成、由右侧3根完整日线确认的更高低点，且与20SMA/EMA20区间下沿相距不超过1ATR、源日收盘仍守住两者时，才可取`min(新低点, 均线带下沿)−0.1ATR`上调。至少提高0.01且低于确认日收盘；仅上移，不放宽。未来合格K线生效，跳空按该K线实际开盘减滑点退出。
7. **独立记账、开户冻结。** 版本进入账户配置哈希与信号身份，`entry_policy`和`trailing_policy`在空账户创建时冻结；已有账户不能补加/切换新政策。旧自动结构账户不再收到新默认BUY，已有订单/仓位按原规则结束；早期默认日线账户也只推进既有订单，不再续加候选。旧两笔历史和固定示例保留。显式非默认参数或指标旧实验沿原规则，不与v2混报。新账户没有登记前成交、估值或收益。
8. **风险与审计。** v2按含双边费用和滑点的初始净风险定仓（默认账户0.35%）；`initial_net_risk_per_share`与原始价差风险分开保存，已实现R仍按初始价差风险标识。订单、持仓和平仓保留`entry_checks`，页面区分登记参考RR、实际开盘净RR、确认/观察/入场时间、等待/拒绝原因以及后续止损证据。

### 逐股每日盈亏

Paper页面按股票和纽约交易日展示每日净盈亏、累计净盈亏、累计已实现/未实现、当日费用、期末数量和估值/退出时间。可筛选单只股票或单个交易日，持仓表另列当前浮动净盈亏。金额为美元，行情时间显示北京时间，交易日日期保持纽约口径。

每笔仓位的累计净贡献：持仓时为`数量×(有效估值−实际买入价)−买入费用`，平仓后采用成交账本的`net_pnl`。每日净盈亏为当日累计净贡献减前一交易日累计净贡献，同股多笔汇总；因此退出日不会重复记入以前的浮盈。买卖费用仅在发生日影响每日结果，滑点已计入成交价，未成交订单不进入盈亏统计。未实现损益不预扣尚未发生的卖出费用。

后续实际处理的有效5分钟K线/日线在`state.daily_marks`保留每仓位每天最后接受的估值、时间及可得来源哈希；不改原成交、现金、权益曲线或移动止损。旧历史只读使用归档收盘行情，标注“依据已归档行情重建”。行情源有修订时，以原权益记录的检查时间精确匹配当次接收回执与K线内容哈希；无法确认版本则保持缺失，不选后来价格重写历史。已平仓记录继承的`mark`可能不是其时间戳对应价格，不用它作为历史估值。

盘中标注未完成日终；缺本日估值、缺上一完整收盘、当前行情中断/过期时，每日盈亏显示不可计算，保留最后已知累计值及实际时间。周末不生成零收益，平仓后不为已结束的单笔交易反复追加记录。不包含分红、拆股和税务会计。

### 旧结构方案（历史与显式旧实验）

日线扫描产生的原始 BUY 自动登记到结构出场基准账户，无需逐只手动加入。止损与目标复用信号日冻结报告中的 `stop`、`target`，依据每只股票的实际结构确定；百分比和盈亏比是据此计算的结果，不是先设定3%／5%或25%再反推价位。

- 视频依据：Google案例将止损放在7/21那根K线低点下方，跌穿即同时破坏20MA、支撑区和趋势线；目标参考前高，见 `VIEWPOINTS.md` E1/H6（44:53–47:05）。3%／5%和25%是风险收益举例，其他案例的距离可以不同。
- 项目现有操作化：E1锚是缺口前leg内最大成交量阳线的低点；止损为 `min(ma_zone.level, trendline.level, E1锚) − 0.1×ATR`，取已有有效候选。`ma_zone.level` 是20EMA／20SMA区间中点；水平结构与E1锚分别保存。0.1×ATR缓冲、候选窗口等是项目假设，不能称为视频给出的精确公式，见 `PRD.md` 操作化清单。
- 目标复用动能峰前21–180日、且高于信号收盘2%的最高已确认pivot high。历史新高等情形没有有效前高时，保留 `target=None`，仅跟踪止损，目标和RR显示不可评估，不填入25%或其他虚构价位。
- 每笔风险计划保留来源报告、信号日、参考锚点及日期、结构价位。模拟买入后按实际含滑点买入价计算止损距离、整数股数量和RR；止损须在实际买入点下方，存在目标时须在买入点上方，失效的计划保留拒绝原因。

例如2026-11-16完整日线报告中，AMGN结构止损412.95、E1锚414.11（9/29），MMM结构止损161.66、E1锚162.13（10/20）；两者均没有可用前高目标。这些是该日结构参考，不是新的买入成交或收益记录，也不应被改成统一3%／5%止损和25%目标。

默认账户权益的 `risk_fraction=0.0035`（0.35%）是每笔价差风险预算，用实际买入价到结构止损的距离计算仓位。默认本金10万美元、买卖手续费各5bps、买卖滑点各5bps，不借款。费用和跳空可使实际亏损超出预算。

### 旧v1持仓移动止损（历史规则）

默认有效的结构前向5分钟账户启用 `structure_ma20_hl_v1`，版本`67b6b6b`已部署，本地与服务器262项测试通过。实际启用、候选与生效回执见部署文档第四轮。视频依据是F2b的20MA出场须留缓冲、F4的强势股沿10/20MA运行，以及G1/G2的高时间框架指导执行。本版选择20日均线、确认更高低点并只上移保护线；组合方式、确认周期、ATR缓冲、美分取整和生效时点是项目操作化假设，不能称为视频给出的完整精确算法。原始BUY判断和初始结构价位不变。

1. **只使用已完成日线。** 源日D以纽约16:30作为保守完成校验门槛，实际行情取得时间另外核验，计算时截断至D；不得使用未收盘日线或后续追加行情。日线负责判断，盘中5分钟K线负责执行，不能把20日均线换成20根5分钟均线。持仓日线独立于当日BUY名单获取，股票不再是BUY仍继续管理已有仓位。
2. **均线候选。** 以20SMA和20EMA区间的下沿为参考，减去 `0.1×ATR(14)`，再向下取整至美分。均线区下沿上升且收盘仍在区间下沿之上时视为支撑候选；若收盘已经跌穿缓冲后的保护位，也可登记该保护位，等待后续真实行情执行，而不是补记源日止损。
3. **结构候选。** 仅使用日期严格晚于入场日的新pivot low，必须由右侧3根完整日线确认，且高于前一个已确认低点。候选同样为低点减 `0.1×ATR(14)` 后向下取整至美分；确认时间、前后低点与价格都留证。
4. **只上移。** 在有效均线候选与结构候选中取较高者，至少高于当前止损0.01美元才上调，否则记录保持不变。此为较紧的OR保护模式，不要求两类条件再次共振，可能比等待全部结构失效更早退出；不会因均线或低点走弱而放宽止损。保护位可以上穿买入价，但跳空和成本仍影响实际结果。
5. **先登记，后生效。** 每份计划保存源日、日线完成门槛、真实取得与观察时间、请求生效时间；只能在源日之后、真实登记及策略启用之后的合格交易时段K线生效，通常为下一实际交易日开盘。迟到登记用登记后的首根合格K线，不把新保护位应用到更早已处理的K线。若生效时开盘已低于新止损，按该实际开盘价减滑点模拟退出，不假定能以更高的止损价成交。
6. **初始风险不变。** 持仓保留 `initial_stop` 与 `initial_risk_per_share`，当前 `stop` 可以上移。初始计划RR及已实现R的风险分母仍用入场时价差风险；净损益扣费用，不用移动后的较小距离或负距离夸大R。目标价保持原初始计划，缺失目标不补固定收益比例。

旧v1发布时曾对既有持仓实际启用并追加版本事件；该迁移过程及两笔原交易保留作为历史，不再重复此做法。新发布不对已有账户补加缺失的移动政策，固定比例、已停用旧示例、日线账户和历史回放保持原规则。

每个账户保存 `trailing_policy`（版本、实际启用时间及说明）、`stop_updates`（已登记判断/计划）与 `stop_adjustments`（实际生效上调）。计划按持仓身份、源日及策略版本去重，保留行情指纹和来源快照；已登记内容不能悄悄改写。`pending` 是待生效计划，不计入实际上调；`applied`、`no_change`、`position_closed` 分别表示已生效、无需上调和持仓已关闭。实际调整保存旧价→新价、请求/实际生效时间、处理时间、MA/EMA、ATR缓冲、pivot与确认日期、候选选择依据及版本，平仓后仍可追溯。

页面区分初始与当前止损、初始风险和R，逐次展示评估与上调记录。没有满足条件的调整时如实显示0次；不为展示效果构造历史调整。日线缓存、哈希、陈旧程度、交易日或企业行动核验失败时，仅暂停相应的新移动止损计算并显示 `monitor.trailing_errors`，有效的原保护位仍由合格5分钟行情执行；5分钟行情本身缺失时继续适用覆盖缺口暂停规则。

### 可选比例实验与历史记录

固定比例仅作为用户主动建立的独立参数实验，不能代替默认结构策略或被称为视频通用规则。原先自动建立的3%／25%、5%／25%账户及其成交原样保留，标记 `automation_disabled=True` 后只读，不再自动登记或推进；新结构账户从实际登记时间开始，不回填旧账户成交或改写其价位与绩效。用户另建指标版本或出场参数仍使用独立账户。

### 前向 5 分钟模型

新默认v2 `forward` 账户使用 `intraday_5m`，入场与结构风控见上文v2规则；与旧结构账户、`daily_ohlc`、比例实验及`replay`分别记账。下列时段、覆盖与会计约束通用，其中旧版本“登记后首次合格K线直接买入”和“无目标仍可买入”只保留在旧实验，不适用于v2。Google原始验收值和冻结BUY判定不改。

1. BUY 来自完整收盘日线；以实际 SPX 行情和交易时段核验下一真实交易日。登记时间取真实可用时间并固定保存，不倒填登记前成交。
2. 仅在信号的下一实际交易日入场。使用该日开盘时间不早于实际登记时间的第一根完整5分钟K线，以开盘加滑点模拟买入；迟到登记可使用当日后续符合条件的K线，超过该交易日则跳过，不顺延补买。
3. 只有已结束、属于真实常规交易时段的K线可推进。结构价位来自登记时已可用的完整日线报告，买入时保存初始风险计划，5分钟行情负责核验是否触发。跳空穿越出场价按K线开盘处理，同根K线同时触及止损和目标时先止损；退出扣滑点与费用。没有目标时仅检查止损。
4. 行情来自真实 Yahoo Finance chart 5分钟OHLCV，不是交易所逐笔成交。触发时间仅精确到K线区间，记录K线时间、实际处理时间与接收时间。来源未核实交易所延迟时明确显示未知，不把每5分钟检查称为无延迟实时成交。
5. 缺少或陈旧的交易日参考行情暂停新买入；个股缺行情、估值陈旧或未处理K线存在覆盖缺口时暂停受影响部分，保留原因及缺口起止时间，不跨缺口假定未触发止损。检测持仓期间拆股时暂停该股，等待企业行动会计核验。
6. 订单与信号按身份去重；恢复执行不重复买卖。权益=现金+持仓市值，净损益扣双边费用；不强制期末平仓，不制造估值或收益，不含现金分红总回报。

第三轮仅按入场结构确定初始价位；本轮进一步加入上述持仓移动止损，按完整日线确认、未来交易时段生效，只提高不下移。分批减仓、10MA模式和零成本持仓等其他视频观点仍未自动化，不混入本版规则。

原有结构日线模型仍按其下一交易日开盘、迟到拒绝、结构价位校验与日内双触发止损优先规则运行。页面区分账户模型，展示待成交结构参考、锚点来源、实际模拟买卖价格/时间、风险距离、仓位、RR、退出原因、费用和净损益。系统不连接券商，也不发出真实股票订单。

运行时 SQLite 保存快照、配置、证据和账户状态，Paper 更新使用进程间锁。数据库与行情在 `/var/lib/multiedge`，与代码发布分离。

## 运行与部署

```bash
python3 -m multiedge.jobs seed --data-dir data --state-dir state
python3 -m multiedge.jobs import-multica --path /path/to/SATU-107 --state-dir state
python3 -m multiedge.app --host 127.0.0.1 --port 8321 --state-dir state

python3 -m multiedge.jobs monitor --state-dir state --data-dir data
```

`daily` 采用纽约16:30之后才允许当日日线的保守截止；周末回到上个工作日，再核验实际 SPX 日期与个股一致。网络错误、失败标的和企业行动问题如实保留，调度器返回失败，不把空结果记成成功。

移动止损使用与账户同源的持仓日线缓存和来源校验，不依赖该股是否仍在扫描BUY结果中。检查过程会取得当前已完成日线、登记新计划，再按实际可用的5分钟K线处理已有保护与生效计划；日线数据错误与盘中报价错误分别留存。

纽约常规交易时段每5分钟触发 `monitor`，收盘后16:05再做尾部检查；纽约工作日18:30的 `daily` 完成日线扫描、结构自动账户登记和收盘复核。修正版已恢复盘中timer，两项定时器均enabled/active；运行回执只包含新结构账户，旧两示例已停用且账本与迁移前备份一致。时区使用 `America/New_York` 跟随夏令时，定时器本身不是交易日历，节假日与提前收盘仍须实际行情时段核验。
