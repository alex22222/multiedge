# 服务器研究与 Paper 平台

## 目标与验收

把已验收的 Multi-Edge 核心放入可持续使用的研究闭环：任务来源 → 候选池 → 单股三层证据 → Paper 验证 → 独立指标实验。持续进度记录在 `LOOP_STATE.md`。

验收要求为页面可访问、原始 Google 基准不漂移、真实任务产物可追溯、缺失数据如实展示、Paper 可对账且不倒填交易、指标配置可版本化。一次扫描不是策略收益验证，测试通过也不等于实盘有效。

## 原始规则与个人实验

`edges.py`、`engine.py`、`Config` 的原始判定规则保持冻结。新增 `experiments.py` 提供两种独立模式：

- `baseline_filter`：原始 BUY 同时满足启用的 RSI/MACD 条件后保留；过滤失败显示 WATCH，不把原始 WATCH/NO 升级。
- `custom`：只按明确启用的个人指标输出实验 BUY/NO，至少启用一个指标；原始判定并列显示。

配置按内容哈希产生不可变版本，名称、模式、周期和阈值均保留。修改配置会产生新版本与独立 Paper 账户，不重写旧结果。

RSI 使用 Wilder 算术均值种子和平滑；全平价格为50，只有上涨为100，只有下跌为0，缺失行情重新暖机。MACD 使用 `adjust=False` 的 EMA，首个价格为种子，快/慢/信号线分别暖机；过滤条件是 `MACD > signal` 的状态，不是当日金叉。

## 三层认识

对应 `VIEWPOINTS.md` C1/C2/C6：

| 层 | 呈现 | 来源边界 |
|---|---|---|
| 认知 | 真实催化剂、基本面驱动、事件日期和原始来源 | 引擎跳空仅为价格代理；没有公告来源时标待核验 |
| 直觉 | 主题、行业领涨、群体联动与资金流证据 | 没有来源时留待研究，不生成假评分 |
| 技术 | 七项边缘、MEA、冻结趋势线、验证清单与退出参考 | 来自保存的引擎输出，不由网页重算 |

页面允许补充认知/直觉证据，记录来源链接、事件日期和实际登记时间。用户记录不自动变成独立核验结论。

## 任务产物与数据源

`jobs import-multica` 只导入真实单股附件和冻结名单。完整名单中的缺失明细显示 MISSING；任务声明的汇总 `claimed_counts` 与已取得明细的 `counts` 分别保存。任务 `in_review` 不能显示成已完成。原始报告缺少图表行情时，只渲染原始 JSON 数字并明确图表缺失。

SATU-107 首次导入时：名单101只，真实单股附件5份，任务记录汇总 BUY2/WATCH44/NO55。该状态会随补充产物形成新的不可变快照；首次导入不代表已独立复跑全部101只。

原始验收缓存仍为 MarketWatch。目标服务器访问该站被要求执行浏览器脚本；新增服务器扫描明确使用 Yahoo Finance chart，并保存到独立 `data/yahoo`。没有默默替换原始缓存，也不把新源结果称为 SATU-107 原始交付。

Yahoo 扫描使用接口 OHLC 的 `Close`，不使用 `Adj Close`。后者会包含分红/拆股调整，见 [Yahoo 官方说明](https://help.yahoo.com/kb/SLN28256.html)。每次请求保存原始 JSON、CSV、哈希、真实区间、纽约交易日期、企业行动和取得时间；命中缓存时验证内容。企业行动总回报不在首版会计范围。

## Paper 规则

第二轮正在工作区实现以下规则；集成测试与服务器部署仍待实际回执，首轮线上状态不代表本轮已发布。

### 两组自动方案

日线扫描产生的原始 BUY 自动登记到两个独立基准账户：`3% 止损 / 25% 止盈` 与 `5% 止损 / 25% 止盈`。无需逐只手动加入；用户另建指标版本或出场参数时使用独立账户，不修改旧记录。

| 方案 | 假设模拟买入价 | 冻结止损 | 冻结止盈 | 计划盈亏比 |
|---|---:|---:|---:|---:|
| 3% / 25% | $100 | $97 | $125 | 约 8.33R |
| 5% / 25% | $100 | $95 | $125 | 5R |

这些是视频举例形成的验证假设，25% 不是收益承诺。8.33R / 5R 未扣费用与滑点；计划止损距离也不保证实际只亏3% / 5%。默认账户权益的 `risk_fraction=0.0035`（0.35%）是每笔价差风险预算，用于根据止损距离计算整数股数量；它与股票的3% / 5%止损距离不同。默认本金10万美元、买卖手续费各5bps、买卖滑点各5bps，不借款。费用和跳空可使实际亏损超出预算。

### 前向 5 分钟模型

新固定比例 `forward` 账户使用 `intraday_5m`，与原有 `daily_ohlc` 结构账户及 `replay` 历史回放分别记账，不混报绩效。原有结构止损、前高目标和 Google 验收值保持原口径；固定比例出场不会改变原始 BUY 判定。

1. BUY 来自完整收盘日线；以实际 SPX 行情和交易时段核验下一真实交易日。登记时间取真实可用时间并固定保存，不倒填登记前成交。
2. 仅在信号的下一实际交易日入场。使用该日开盘时间不早于实际登记时间的第一根完整5分钟K线，以开盘加滑点模拟买入；迟到登记可使用当日后续符合条件的K线，超过该交易日则跳过，不顺延补买。
3. 只有已结束、属于真实常规交易时段的K线可推进。入场后按含买入滑点的模拟成交价冻结止损与止盈。跳空穿越出场价按K线开盘处理，同根K线同时触及止损和止盈时先止损；退出扣滑点与费用。
4. 行情来自真实 Yahoo Finance chart 5分钟OHLCV，不是交易所逐笔成交。触发时间仅精确到K线区间，记录K线时间、实际处理时间与接收时间。来源未核实交易所延迟时明确显示未知，不把每5分钟检查称为无延迟实时成交。
5. 缺少或陈旧的交易日参考行情暂停新买入；个股缺行情、估值陈旧或未处理K线存在覆盖缺口时暂停受影响部分，保留原因及缺口起止时间，不跨缺口假定未触发止损。检测持仓期间拆股时暂停该股，等待企业行动会计核验。
6. 订单与信号按身份去重；恢复执行不重复买卖。权益=现金+持仓市值，净损益扣双边费用；不强制期末平仓，不制造估值或收益，不含现金分红总回报。

原有结构日线模型仍按其下一交易日开盘、迟到拒绝、结构价位校验与日内双触发止损优先规则运行；缺结构目标可仅跟踪止损。页面区分账户模型，展示待成交计划比例，以及实际模拟买卖价格/时间、冻结价位、退出原因、费用和净损益。系统不连接券商，也不发出真实股票订单。

运行时 SQLite 保存快照、配置、证据和账户状态，Paper 更新使用进程间锁。数据库与行情在 `/var/lib/multiedge`，与代码发布分离。

## 运行与部署

```bash
python3 -m multiedge.jobs seed --data-dir data --state-dir state
python3 -m multiedge.jobs import-multica --path /path/to/SATU-107 --state-dir state
python3 -m multiedge.app --host 127.0.0.1 --port 8321 --state-dir state
python3 -m multiedge.jobs daily --provider yahoo --state-dir state --data-dir data
python3 -m multiedge.jobs monitor --state-dir state --data-dir data
```

`daily` 采用纽约16:30之后才允许当日日线的保守截止；周末回到上个工作日，再核验实际 SPX 日期与个股一致。网络错误、失败标的和企业行动问题如实保留，调度器返回失败，不把空结果记成成功。

第二轮计划由纽约常规交易时段每5分钟触发 `monitor`，收盘后16:05再做尾部检查；纽约工作日18:30的 `daily` 完成日线扫描、两组自动账户登记和收盘复核。时区使用 `America/New_York` 跟随夏令时，定时器本身不是交易日历，节假日与提前收盘仍须实际行情时段核验。本轮定时器启用、真实行情检查与部署结果待根任务取得服务器回执后记录。
